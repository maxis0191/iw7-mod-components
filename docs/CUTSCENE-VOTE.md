# Cooperative cutscene skipping

The server owns a fresh ballot per retail Bink video. Each current connected
player must hold one of Space, Enter or left mouse for two uninterrupted
seconds; the displayed hint names Space only. A key already held when the
video starts needs a release first. Votes survive release, but not a replaced
connection. Joiners enter the denominator and disconnected players leave it.
One player therefore skips after their own two-second hold.

The client input bridge sends bounded epoch/mask heartbeats over the existing
client command channel. Expired heartbeats release all keys. A normal client
without this component retains native jump/fire voting; physical Enter needs
the updated standard client. No voice protocol or advertised mod changes.

The GSC worker retains retail control freeze, Bink omnvar and black-fade cleanup.
Stopping video alone is insufficient: quest callers have separate fixed waits.
The native loader observes selected original ScriptFiles before linking, uses
the pinned xsk instruction decoder, and redirects selected OP_wait instructions
through small frame-preserving continuations. No retail source is distributed.
Each thunk consumes the original numeric duration, polls its own thread state,
and returns through a redirect sentinel to the next original instruction.
Self, local variables, endon and the retail callback sequence stay intact.

Only the seven known quest videos and their named dependent waits are eligible.
The active movie's remaining duration is removed from those deadlines after
the worker clears Bink and unfreezes players. Post-video margins remain native.
MissingReel's combat timeout is excluded. Beast's decorative projector loops
are excluded. Unknown or ambiguous named wait layouts disable skipping for that movie.
